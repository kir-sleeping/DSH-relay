# Relay 接入示例 · 收件箱小报

版本：v1（方案，未实现）
目标：一个单文件 HTML，把 Relay 的两种请求方式都演示清楚，同时是给人和给 AI 读的参考实现。

---

## 0. 这个示例要证明什么

- 应用自己没有 AI，全部能力来自 Relay。
- **应用把自己的数据交出去**（整批邮件的结构化数据），不是让用户复制粘贴。
- 两种请求方式在同一个页面里各有各的形态：用户点的、和应用自己在后台发的。
- 后台请求要能被程序消费：**让 agent 输出可解析的结构，解析失败要能自愈**。

不做：真实收发邮件、真实定时器（用按钮模拟）、多账号、附件。

---

## 2. 数据模型

### 2.1 邮件（页面内置，模拟数据）

```js
{
  id: 'm1',                       // 稳定标识，回传和跳转都用它
  from: '张伟',
  subject: '周三评审会材料',
  receivedAt: '2026-11-14T10:24:00+08:00',
  url: 'https://mail.example.com/m1',   // 原样发给 agent，再原样要回来
  body: '……'
}
```

`url` 必须在输入里给出，并要求 agent **原样回传**——这是"应用数据出去再回来"的最小证据，比让 agent 自己编链接可靠。

### 2.2 小报条目

```js
{ id: 'm1', importance: 3, summary: '合同今天到期，需在 18:00 前回复', url: 'https://…' }
```

`id` 和 `url` 必须能对回输入里的邮件；`summary` 一句话；`importance` 整数，越大越重要。

## 3. 两种请求

### 3.1 主动：起草回复

| 项 | 值 |
|---|---|
| 触发 | 用户点「起草回复」 |
| `trigger` | `"user"`（用户点了按钮） |
| `stream` | `true`，边生成边写进草稿框 |
| `timeout` | 120 秒 |
| 失败 | 就地提示，允许重试 |

内容里带邮件的结构化数据（发件人、主题、正文），并说明期望的语气。用户点「再正式一点」时，只发这一句 + 上一稿，靠**同一会话**的连续性完成改写。

### 3.2 后台：每日小报

| 项 | 值 |
|---|---|
| 触发 | 按钮「生成每日小报」——**注释说明真实部署是每天定时触发**（`setInterval` / 系统计划任务 / 后端 cron），示例用按钮只为可演示 |
| `trigger` | `"app"`（应用自己发的） |
| `stream` | `false`，一次性拿完整结果 |
| `wait` | `true`，`timeout` 90 秒；返回 202 则按 1.5 秒间隔轮询到 120 秒 |
| 失败 | **静默**：不弹提示，只在页面上留一行淡色状态；格式错误自动重试一次 |

内容 = 任务说明 + 全量邮件的 JSON。

**注意**：级别 1/2 下这条后台请求仍会弹确认框——因为它标的是 `trigger: "app"`。想真正静默，需要用户在「设置 → 应用权限」里把本应用调到级别 3。示例要在注释里写明这一点，并建议演示前先调好级别。

## 4. 结构化输出：协议、校验、自愈

### 4.1 请求里的提示词（原文）

```text
下面是过去一天收到的邮件，每封有 id、发件人、主题、时间、链接、正文。

请生成一份小报：按重要性从高到低排序，每封给一句话总结（不超过 30 字）。

只输出 JSON，不要任何解释，不要 Markdown 代码块。格式：
{"digest":[{"id":"邮件id","importance":3,"summary":"一句话","url":"邮件的链接"}]}

importance 是整数，越大越重要，条目必须按 importance 从大到小排列。
id 和 url 必须原样取自输入，不要改写，不要新增。

邮件数据：
<JSON>
```

### 4.2 校验规则

解析前先容错：去掉 ```json 围栏，取第一个 `{` 到最后一个 `}`。

逐条校验：

1. 顶层是对象，`digest` 是数组且非空。
2. 每项字段齐全，类型正确。
3. `id` 必须存在于输入邮件集合，且不重复。
4. `url` 必须与输入里同 `id` 的 `url` 完全一致。
5. `summary` 非空，长度 ≤ 60。
6. `importance` 是整数。
7. 顺序：`importance` 单调不增。

任一条不满足即判为格式错误。

### 4.3 自愈

格式错误时**自动重发一次**，内容为：

```text
上一次输出无法解析，原因：{第一条失败原因}。
只输出 JSON，不要解释，不要代码块。格式必须是：
{"digest":[{"id":"…","importance":3,"summary":"…","url":"…"}]}
```

只重试一次。仍失败则把原始输出折叠显示在小报区（方便排查），并在注释里说明：**真实产品应该在这里加指数退避或降级到纯文本摘要，示例不铺开**。

## 5. 授权与凭证

1. 页面读 `localStorage['relay.fingerprint.<source>']`。
2. 没有就在**第一次调用前**申请：`POST /fingerprint {source}`，会弹出系统确认框，用户点「允许」后拿到凭证，存进 localStorage。
3. 之后每次请求带 `source + fingerprint`。
4. 拿到 401（凭证失效或被删）→ 清掉本地凭证 → 重新申请一次 → 重试当前调用**一次**。
5. 页面顶部显示当前级别：申请成功后读一次 `GET /sources`，按 `source` 找自己那行。级别为 1/2 时给一行提示：把应用调到级别 3 才能让后台请求真正静默。

`source` 固定为 `inbox-demo`。

## 6. 错误处理矩阵

| 情况 | 判定 | 主动请求 | 后台请求 |
|---|---|---|---|
| 400 | 请求写错 | 显示 code/message | 静默记录，不重试 |
| 401 `ERR_INPUT_FINGERPRINT` | 凭证缺失/失效 | 清凭证 → 重申请 → 重试一次 | 同左，失败则静默 |
| 403 `ERR_ACCESS_DENIED` | 来源被禁 | 提示去设置解除 | 静默停用本次 |
| 403 `ERR_AUTH_DENIED` | 用户当场拒绝 | 提示"已拒绝" | 静默，不重试 |
| 409 `ERR_SESSION_OUTSIDE_WORKSPACE` | 会话不在工作区 | 提示改用 `main` | 同左 |
| 410 `ERR_QUEUE_EXPIRED` | 排队超时作废 | 提示并允许重试 | 自动重试一次 |
| 503 `ERR_AUTH_UNAVAILABLE` | 主机没有桌面 | 提示到主机操作 | 静默停用 |
| 504 `ERR_AUTH_TIMEOUT` | 确认超时 | 提示重试 | 静默 |
| 202 | 还没好 | 轮询 | 轮询 |
| 200 + `type:"error"` | 任务执行失败 | 显示 code/message | 静默 + 记录 |
| 网络错误 | 连不上 | 提示检查服务 | 静默重试一次 |

原则：**主动请求的错误要让人看见并能重试；后台请求的错误要让人看不见，但代码里留下痕迹。**

## 7. 代码组织

单文件，按顺序分段，每段前有说明性注释：

1. `CONFIG` —— 地址、source、存储键、超时。
2. `transport` —— 统一的 `call(path, body)`：拼地址、发请求、按状态码分类抛出带 `kind` 的错误。
3. `auth` —— 凭证的读取、申请、失效重取。
4. `relay` —— 三个入口：`submit()`、`waitResult()`、`streamSubmit()`，以及 `ask({content, trigger, stream})` 这一层封装。
5. `digest` —— 提示词构造、解析、校验、重试。
6. `ui` —— 渲染与事件绑定。
7. `data` —— 模拟邮件。

注释面向 AI 读者：说清"为什么"，不是"是什么"。尤其要写清：

- 为什么两条路径的 `trigger` 不同，以及为什么"用户放行"不等于"用户说的"；
- 为什么后台请求不流式；
- 为什么校验要这么严（agent 输出是自由文本，不是 API）；
- 为什么重试只有一次。

## 8. 验收

```
□ 首次打开点「起草回复」→ 弹系统确认框 → 允许 → 草稿流式出现
□ 点「再正式一点」→ 基于上一稿改写，说明同会话上下文生效
□ 点「生成每日小报」→ 不流式，几秒后按重要性排出条目，每条带可点击链接
□ 小报里的链接能定位到左侧对应邮件
□ 级别 1/2 下后台请求会弹确认框；调到 3 后静默
□ 删掉 localStorage 里的凭证再点按钮 → 自动重新申请并继续
□ 服务停掉再点按钮 → 提示连不上，不白屏
□ 手动把 agent 返回改成非法 JSON（临时改提示词）→ 触发一次重试 → 仍失败则折叠显示原始输出
```

---

## 9. 取舍

- 定时器用按钮模拟，注释说明真实形态——否则打开页面就发请求，反而妨碍阅读代码。
- 只重试一次，不铺开退避策略。
- 不做回复的"发送"，草稿留在框里——发送是邮件协议的事，和 Relay 无关。
- 邮件是内置模拟数据，不从真实邮箱读——示例的重点是调用方式，不是邮件客户端。
